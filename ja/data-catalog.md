データカタログは、パブリッシュしたデータを一か所にまとめて、探して、再利用するための場所です。パブリッシュしたデータは、ほかのプロジェクトで再利用できます。更新のスケジュールを決めると、指定した時刻に更新できます。さらに、AI エージェントからも探せます。

データカタログには 2 種類あります。

- **サーバー**: Exploratory サーバー（exploratory.io）にパブリッシュしたデータ。チームのメンバーと共有できます
- **ローカル**: この PC に保存するデータ。サーバーに上げなくても、一覧、検索、スケジュール更新、AI エージェントからの利用ができます

どちらも、データフレームのパブリッシュダイアログから登録します。

## データをカタログにパブリッシュする

1. プロジェクトで、カタログに載せたいデータフレームのステップを選び、「パブリッシュ」ボタンを押します
2. パブリッシュダイアログの「パブリッシュ先」で、「サーバー」と「ローカル」のどちらか、または両方にチェックを入れます
   - **サーバー**: 「Exploratoryサーバーで共有」「サーバーでスケジュール可能」
   - **ローカル**: 「このPC上に保存」「このPC上でスケジュール可能」
3. タイトル、説明、タグを入力します。説明の欄の「AI」ボタンを押すと、AI がデータを読み取って、説明を作ります
4. 「パブリッシュ」を押します

ローカルだけにパブリッシュすると、「データカタログにパブリッシュしました」と表示されます。データは、プロジェクトの一覧が表示されるウィンドウの「データカタログ」タブに並びます。

オフラインモードのときは、「サーバー」を選べません。オフラインモードを解除していても、サインインが切れていると、サーバーにはパブリッシュされません。両方にチェックを入れていた場合は、ローカルにだけ保存されます。サインインして、もう一度パブリッシュしてください。

すでにパブリッシュしたデータを更新するときは、同じ手順でもう一度パブリッシュします。サーバーへのパブリッシュでは、「変更メモ」を書くと、バージョン履歴に残ります。

## 一覧から探す

プロジェクトの一覧が表示されるウィンドウの「データカタログ」タブに、この PC のローカルデータカタログが一覧で並びます。

- 検索欄では、「名前」「説明」「タグ」「列名」のどれを対象にするかを選んで検索できます。一致したタグや列名は、データ名の下に「一致」として表示されます
- 並べ替えは、更新日が新しい順、古い順、名前順（昇順・降順）から選べます
- 一覧には、データ名、元のプロジェクト、行数、更新日、スケジュール、更新の状態（成功、失敗、実行中）、MCP のチェックが並びます
- データ名をクリックすると、詳細の画面が開きます

詳細の画面には、次のタブがあります。

| タブ | 内容 |
| --- | --- |
| サマリ | データの概要 |
| テーブル | データの中身。絞り込みや並べ替えもできます |
| メタデータ | 説明、タグ、列ごとの説明。「AIで生成・改善」では、データの概要、列の説明、セマンティクスを AI が作成、改善します |
| 加工ステップ | データを作るまでの加工ステップ |
| ソース | データの取得元 |
| アクセスログ | AI エージェント（MCP）からのアクセスの記録 |

右上の「⋯」のメニューからは、次の操作ができます。

- **保存フォルダを開く**: データが保存されているフォルダを開く
- **再パブリッシュ**: 元のデータフレームのパブリッシュダイアログを開く。元のプロジェクトやデータフレームが見つからないときは使えません
- **EDF としてエクスポート**: データを EDF ファイルとして書き出す
- **削除**: カタログから削除する。この PC に保存されたファイルも削除されます

## カタログのデータをインポートする

1. データのインポートのメニューで、「データ・カタログ」を選びます
2. 「データカタログからインポート」ダイアログの上のほうで、「サーバー」か「ローカル」を選びます
3. 検索して、インポートしたいデータを選びます
4. 必要に応じて、フィルター、列の選択、ほかのカタログのデータとの結合、集計を設定します
5. 「インポート」を押します

ローカルのタブでは、すでに取り込んだデータに「取り込み済み」と表示されます。全データが保存されていないデータは、インポートできません。元のプロジェクトで、もう一度パブリッシュしてください。

選んだデータは、このプロジェクトにデータフレームとして取り込まれます。取り込んだあとに「更新」を押すと、同じ条件で最新のデータを読み直します。すでにあるデータフレームのデータソースを、カタログのデータに差し替えることもできます。

## スケジュールで更新する

ローカルのデータは、時刻を決めて定期的に更新できます。詳細の画面の時計のボタンから、スケジュールのダイアログを開きます。

- 繰り返しのタイプは、「毎月」「毎週」「毎日」「毎時間」「N分おき」から選べます
- タイムゾーンと終了日も指定できます。「次回の実行」で、次に動く日時を確認できます
- 更新では、パブリッシュしたときのデータソースからデータを読み直し、加工ステップをもう一度実行して、データを置き換えます
- OS にバックグラウンド更新を登録できたときは、アプリを閉じていても実行します。登録できなかったときは、アプリを開いている間に更新し、未実行分は次にアプリを起動したときに 1 回更新します（Windows では、サインインしたときにも更新します）
- 失敗したときや成功したときに、PC に通知を出す設定もあります
- 「実行結果」タブで、直近の実行の開始時刻、結果、行数、所要時間を確認できます。止めるときは、「繰り返しのタイプ」を「なし」にします

更新できないデータもあります。たとえば、データソースがスナップショットとしてパブリッシュされているデータや、更新に対応していないデータソースを使っているデータです。データソースのファイルが見つからないときも、更新に失敗します。ファイルをこの PC の同じ場所に置くか、元のプロジェクトでデータソースを更新して、もう一度パブリッシュしてください。理由は、一覧の更新の状態にポインタを合わせると確認できます。

サーバーにパブリッシュしたデータの更新は、サーバーのスケジュールで行います。くわしくは、[スケジュール](/ja/schedule/manage)をご覧ください。

## AI エージェント（MCP）から使う

AI エージェント（Claude など）から、ローカルのデータカタログを検索して、データを読んだり、絞り込み、集計、結合をしたりできます。一覧の「MCP」の列にチェックを入れたデータだけが、AI エージェントから見えます。チェックを外すと見えなくなります。

## サーバーのデータカタログで AI に答えさせる

サーバーのデータカタログでは、パブリッシュしたデータに「セマンティクス」を付けられます。セマンティクスは、そのデータの意味を AI に伝えるための定義です。AI エージェントは、列の名前だけでは分からないことを、この定義から読み取ります。たとえば、1 行が何を表すのか、どの列を合計してよいのか、キャンセルを含めるのか、といったことです。

### AI で生成して、人が承認する

データのページの「メタデータ」タブで、「AIで生成・改善」を押します。AI が、データの概要、列の情報、統計、加工の手順などをもとに、セマンティクスの下書きを作ります。定義は、次の 5 つに分かれています。集計ルールは、お使いのサーバーの設定で有効なときだけ生成されます。

| 区分 | 定義する内容 |
| --- | --- |
| データセットの意味 | データの粒度（1 行が何か）、主な日付列、分析対象と対象外、加工内容の概要、更新状況 |
| 列の意味と役割 | 列ごとの用途と集計方法 |
| ビジネス指標 | このデータから計算する主要な指標と、その計算方法 |
| 集計ルール・注意点 | 正しく集計し、解釈するためのルール |
| 質問と集計例 | よく使う質問と、その正しい集計方法 |

下書きの内容は、そのままでは公式の定義になりません。「AI提案あり」と表示された項目を、データの所有者が確認して、「承認」または「却下」を選びます。承認した項目が、公式の定義として AI エージェントに渡ります。承認済みの項目を書き換えて保存すると、承認が外れるので、もう一度承認してください。

データの一覧の「AI 対応」の列で、準備の状況を確認できます。状態は、「準備完了」「要確認」「下書き」「未設定」です。

### 必要な集計結果だけを AI に渡す

`query_dataset` で集計を頼むと、サーバーが DuckDB で絞り込み、グループ化、集計、結合を計算します。AI エージェントは、データの行を何ページも読まなくても、集計した結果を受け取れます。元の行を取得する指定や、ほかの読み取りの道具では、返った行も会話の一部になります。くわしくは、[Server MCP のデータと権限](/ja/mcp/server/data)をご覧ください。

### サーバー MCP から使う

サーバーの MCP からは、承認済みのセマンティクスを使って、データを探し、集計できます。

- `dataframe_get_schema` は、詳細（`full`）で取得すると、承認された定義を返します。データの変更などで「要再確認」になった定義には、警告が付きます。AI はこの定義を、集計の前に読みます
- `query_dataset` は、データをサーバーで絞り込み、集計します。オンプレミスのサーバーでは、管理者が有効にしたときだけ使えます

データの所有者は、データごとに MCP からのアクセスを止められます。サーバーの「データカタログ」で、対象の行の「⋮」から「アクセス設定」を開き、「MCP アクセス」の「有効にする」のチェックを外して、「適用」を押します。

道具の使い方と、記録される内容は、次のページをご覧ください。

- [Server MCP の道具](/ja/mcp/server/tools)
- [Server MCP のデータと権限](/ja/mcp/server/data)

## サーバーとローカルの違い

| | サーバー | ローカル |
| --- | --- | --- |
| 保存場所 | Exploratory サーバー | この PC |
| 共有 | チームのメンバーと共有できる | この PC だけ |
| 検索の対象（インポートのダイアログ） | 名前、説明、タグ、作成者 | 名前、説明、タグ、列名 |
| 更新のスケジュール | サーバーで実行 | この PC で実行（OS に登録できたときは、アプリを閉じていても実行） |

インポートのダイアログの「サーバー」タブでは、サーバーのデータを「自分のデータ」「チームのデータ」「共有されたデータ」に分けて探せます。パブリッシュの手順や共有の設定は、[データの共有](/ja/share/data)をご覧ください。
